# 安装、保存与备份

## 本机运行

1. 安装 [Node.js 24.15+](https://nodejs.org/)，打开终端运行 `node --version` 检查版本。
2. 下载并解压仓库，进入包含 `package.json` 的文件夹。
3. 运行 `npm start`，打开 http://127.0.0.1:3000。
4. 导入自己的 PDF；只有显示保存完成，资料才已写入数据目录。

Windows 可以在资源管理器进入项目文件夹，在地址栏输入 `powershell` 后回车，再运行启动命令。macOS / Linux 用户在终端进入该文件夹运行即可。无需安装 npm 依赖或构建应用。

这是单人本机服务，只有当前电脑能够访问。关闭浏览器不会停止服务；终端按 Ctrl+C 停止服务，下次运行同一命令可继续使用。

## 演示与自己的资料分开

```bash
npm run demo
```

默认演示目录是 `data/demo/`，正常目录是 `data/`。运行其中一个服务前先停止另一个，避免默认端口被占用。演示会创建合成 PDF，不会下载真实论文，也不会上传你的资料。

## 自定义目录与端口

把 `.env.example` 复制成 `.env`。例如：

```dotenv
PAPERLOOM_PORT=3001
PAPERLOOM_DATA_DIR=./my-library
PAPERLOOM_CROSSREF=off
```

然后运行：

```bash
node --env-file=.env server/index.mjs
```

数据目录由你设置后，发布代码前也要把自定义目录加入 `.gitignore`。默认 `data/` 已被排除。不要把数据目录放进 `public/`。

## 备份

首选界面中的 **导出资料 → 完整备份（含 PDF）**。仅导出资料不会包含 PDF 原文件。

恢复时选择 **导入 PDF → 从 Paperloom 备份恢复**。可用于迁移到另一台电脑。当前版本不会自动在两台电脑间同步。

也可以停止服务后复制整个数据目录。若 SQLite 的 `-wal`、`-shm` 文件还存在，也应一并保留。不要只复制运行中的 `.sqlite` 主文件。

## 升级

1. 导出完整备份并停止服务。
2. 更新代码，保留自己的数据目录和 `.env`。
3. 重新运行 `npm start`。尚未应用的 SQL 迁移会自动按顺序执行。
4. 检查资料和 PDF 是否完整，再继续使用。

迁移记录保存在数据库的 `_migrations` 表中。修改过的旧迁移不会自动重跑；结构变更应新增 SQL 文件。

## 常见问题

### 端口已被占用

先停止旧的 Paperloom 终端，或设置其他 `PAPERLOOM_PORT`。浏览器应打开启动日志显示的地址。

### 翻译按钮显示不支持

使用支持 Translator API 的最新版桌面 Chrome / Edge。浏览器发行版、企业策略和语言包下载情况都会影响可用性。手机浏览器暂不支持。翻译不是服务端 API，不需要密钥；首次模型准备失败时可检查网络后重试。

### PDF 没识别出摘要或作者

检查 PDF 是否有可复制的文字层。元信息来自文档文字与属性，识别完整性取决于排版与原文件。可直接编辑论文信息；OCR 尚未接入。

### 删除后磁盘空间没有减少

当前删除属于移入回收站，保留原文件与笔记以便恢复。自动清理、永久删除与容量统计尚未实现。

### 浏览器清缓存后，论文还在吗

已经写入数据目录的资料仍然存在。未完成同步、只留在浏览器中的操作可能丢失，因此应以保存状态为准。

## 关于公网部署

这个启动器固定绑定 `127.0.0.1`，提供单人本机身份，没有公众注册、密码登录和公网访问授权。

**不要通过隧道或反向代理直接开放这个单人接口。** 公网版本需要实现真实身份认证适配器、账号级授权、上传与存储配额、请求频率控制、HTTPS、备份与恢复方案。业务层保留了按 owner_id 隔离记录的接口，相关扩展见 [架构说明](ARCHITECTURE.md)。

当前仓库不依赖某个私人网站、云平台项目 ID 或维护者的账号。
